# Проверка запросов в API ExtraReality

На этой странице описано, как убедиться, что запрос к вашим эндпоинтам действительно от нас.
Это относится ко всем API, описанным здесь: [Events API](EventsAPIv1.md), [Games API](GamesAPIv1.md)
и эндпоинтам заявок из [Form Object](FormObject.md).

## Что мы отправляем

Каждый запрос содержит эти заголовки:

| Заголовок           | Пример                           | Описание                                       |
|---------------------|----------------------------------|------------------------------------------------|
| `X-Source`          | `extrareality`                   | Какой из наших сайтов вызывает. Все они используют секрет, согласованный с вами |
| `X-Timestamp`       | `2025-05-10T17:00:00+00:00`      | Когда создан запрос, ISO 8601 в UTC            |
| `X-Signature-256`   | `9f86d081...`                    | Подпись HMAC-SHA256 в hex                      |

Всё необходимое для проверки запроса — в этих заголовках. В query string и в теле form data мы ничего не добавляем, поэтому поля, которые вы получаете, — только ваши.

**Настоятельно рекомендуем проверять подпись до обработки запроса**, чтобы никогда не отдавать свои данные — включая персональные данные зарегистрировавшихся людей — постороннему, который просто угадал URL.

На одном эндпоинте это не рекомендация, а требование: эндпоинт
[контакты участников](EventsAPIv1.md#контакты-участников) возвращает адреса email, поэтому
он должен отклонять любой запрос, подпись которого не проходит проверку.

## Как формируется подпись

`X-Signature-256` — это HMAC-SHA256 канонической строки, ключом служит секрет, известный только вам и нам. Каноническая строка — пять частей, соединённых переводом строки (`\n`):

```
X-Source header
X-Timestamp header
HTTP method, uppercase, e.g. GET or POST
request target — path and query string, exactly as it arrived, e.g. /api/events?city=1
SHA-256 of the raw request body, hex encoded (of an empty string for GET)
```

В PHP:

```php
$canonical = implode("\n", [
    $source,
    $timestamp,
    $method,
    $requestTarget,
    hash('sha256', $rawBody),
]);

$signature = hash_hmac('sha256', $canonical, $secret);
```

Три свойства этой схемы стоит знать — каждое из них вы получаете только если проверяете подпись именно так, как описано здесь:

* **Тело запроса подписано.** Изменение одного байта в том, что мы отправляем, делает подпись недействительной, поэтому никто не сможет переиспользовать однажды увиденную подпись, чтобы отправить произвольные данные регистрации на ваш эндпоинт заявок.
* **HMAC, а не простой хеш.** Конкатенация секрета с данными и хеширование — наивная конструкция с известными слабостями. HMAC — стандартный, хорошо изученный способ ключевого хеширования.
* **Запрос привязан к цели.** Подпись, перехваченная на публичном списке мероприятий, не может быть воспроизведена против вашего эндпоинта регистрации.

### Verifying it

```php
function verifyExtrarealityRequest(string $secret, int $maxAgeSeconds = 300): bool
{
    $source    = $_SERVER['HTTP_X_SOURCE'] ?? '';
    $timestamp = $_SERVER['HTTP_X_TIMESTAMP'] ?? '';
    $received  = $_SERVER['HTTP_X_SIGNATURE_256'] ?? '';

    // Reject stale requests, otherwise a captured signature is valid forever
    $ts = strtotime($timestamp);
    if ($ts === false || abs(time() - $ts) > $maxAgeSeconds) {
        return false;
    }

    $canonical = implode("\n", [
        $source,
        $timestamp,
        $_SERVER['REQUEST_METHOD'],
        $_SERVER['REQUEST_URI'],
        hash('sha256', file_get_contents('php://input')),
    ]);

    $expected = hash_hmac('sha256', $canonical, $secret);

    // hash_equals, not "==", to avoid leaking the answer through timing
    return hash_equals($expected, $received);
}
```

Три детали, которые легко испортить:

* **Сравнивайте через `hash_equals()`**, никогда через `==` или `===`. Обычное сравнение возвращает результат, как только встречает отличающийся байт, и этой разницы во времени достаточно, чтобы восстановить корректную подпись побайтно.
* **Хешируйте сырое тело** до любого разбора. Если фреймворк уже декодировал JSON, не перекодируйте его — порядок ключей и экранирование будут другими, и подпись не совпадёт. В Laravel используйте `$request->getContent()`, в Symfony — `$request->getContent()`, в чистом PHP — `php://input`.
* **`REQUEST_URI` должен быть целью запроса в том виде, в каком она пришла.** Если прокси или правило rewrite перед приложением меняет путь, подписывайте значение, которое приложение реально получает, и сообщите нам, чтобы мы договорились об этом.

### Временное окно

Рекомендуем отклонять всё старше **5 минут**. Без такого окна подпись, утёкшая один раз — через лог, прокси, отчёт об ошибке — остаётся действительной навсегда, и вся схема подписи не защищает от повторного воспроизведения.

Если часы расходятся, эта проверка начинает отклонять корректные запросы. Держите NTP включённым.

## О секрете

* Мы можем сгенерировать случайный секрет или согласовать его с вами заранее. Просите минимум 32 случайных символа — на этом держится надёжность всего описанного выше.
* Это общий секрет, а не публичный идентификатор. Не храните его в репозитории, на фронтенде и в логах.
* Если подозреваете утечку, сообщите нам — мы выполним ротацию.

## HTTP-коды статуса

Если вы отклоняете запрос из-за неверной подписи, отвечайте `403` с телом:

```json
{"success": false, "message": "Invalid signature"}
```

Отклонённая подпись — не проблема пользователя, заполняющего форму, которую он может исправить, поэтому ответ не должен выглядеть как таковая. `403` также не попадает в ваши метрики успеха — именно туда и нужно, если кто-то начнёт прощупывать ваши эндпоинты.

Полная таблица кодов статуса и то, что мы делаем с каждым ответом, — в [Ответы и ошибки](Responses.md).
